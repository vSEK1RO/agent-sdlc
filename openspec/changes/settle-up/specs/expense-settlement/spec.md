# Spec Delta

## Purpose

Описывает поведение команды расчёта: как по балансам группы получить список денежных переводов, гарантированно минимальный на небольших группах и корректный на больших.

## ADDED Requirements

### Requirement: Settlement plan from balances

Система SHALL строить план переводов из балансов в копейках. Каждый перевод MUST переводить положительную сумму от участника с отрицательным балансом участнику с положительным балансом; после применения плана чистый результат каждого участника MUST равняться его балансу.

#### Scenario: Two participants

- **GIVEN** балансы: Аня `+50_000`, Боря `−50_000` копеек
- **WHEN** запрошен план расчёта
- **THEN** план содержит ровно один перевод Боря → Аня `50_000` копеек, и чистый результат каждого участника равен его балансу

#### Scenario: Three participants after one shared expense

- **GIVEN** Аня заплатила `900_00` копеек за троих; балансы: Аня `+60_000`, Боря `−30_000`, Вика `−30_000`
- **WHEN** запрошен план расчёта
- **THEN** план содержит Боря → Аня `30_000` и Вика → Аня `30_000` копеек

### Requirement: Minimum number of transfers for small groups

При `m ≤ 14` участниках с ненулевым балансом система MUST выдавать план с глобально минимальным числом переводов.

#### Scenario: Greedy algorithm would be suboptimal

- **GIVEN** балансы: Аня `+60_000`, Боря `+40_000`, Вика `−40_000`, Гоша `−40_000`, Дима `−20_000`
- **WHEN** запрошен план расчёта
- **THEN** план содержит 3 перевода: Вика → Боря `40_000`, Гоша → Аня `40_000`, Дима → Аня `20_000` копеек

#### Scenario: Karelia example

- **GIVEN** данные `examples/karelia.json` с шестью ненулевыми балансами
- **WHEN** выполнена команда `skinemsya --file examples/karelia.json settle`
- **THEN** напечатано 4 перевода: Гоша → Боря `200_000`, Гоша → Вика `200_000`, Дима → Аня `400_000`, Егор → Аня `300_000` копеек

### Requirement: Bounded fallback for large groups

При `m > 14` участниках с ненулевым балансом система MUST выдавать корректный план не более чем из `m − 1` переводов и MUST NOT называть его минимальным.

#### Scenario: Fifteen participants

- **GIVEN** 15 ненулевых балансов, сумма которых равна нулю
- **WHEN** запрошен план расчёта
- **THEN** план корректен, содержит не более 14 переводов и не позиционируется как минимальный

### Requirement: Deterministic plan

План MUST быть детерминированным и отсортированным по `(debtor, creditor, amount)` независимо от порядка участников во входных данных.

#### Scenario: Same balances in different order

- **GIVEN** два одинаковых набора балансов с разным порядком ключей
- **WHEN** план запрошен дважды
- **THEN** оба списка переводов идентичны и отсортированы по `(debtor, creditor, amount)`

### Requirement: Invalid balances are rejected

Если сумма балансов не равна нулю, система MUST отвернуть запрос с ошибкой; CLI MUST вернуть код возврата `2`.

#### Scenario: Unbalanced input

- **GIVEN** балансы Аня `+100`, Боря `0` копеек
- **WHEN** запрошен план расчёта через CLI
- **THEN** в stderr напечатано сообщение об ошибке «Балансы не сходятся», и код возврата равен `2`

### Requirement: No transfers when nothing to settle

Когда все балансы нулевые или группа пуста, система MUST вернуть пустой план; CLI MUST напечатать `Переводы не нужны.` и вернуть `0`.

#### Scenario: Empty group

- **GIVEN** группа без трат
- **WHEN** выполнена команда `skinemsya settle`
- **THEN** напечатано `Переводы не нужны.`, строк с переводом нет, код возврата равен `0`
