# Proposal

## Why

Команда `balance` показывает, кто в плюсе и кто в минусе, но не отвечает на вопрос пользователя «кому мне переводить?». В поездке из issue #2 друзья посчитали в Excel 11 переводов, запутались и заплатили дважды; чем меньше переводов, тем проще всем рассчитаться.

## What Changes

- Добавляется команда `skinemsya settle` и публичный Python API `settle(group)` / `settle_balances(balances)` для плана переводов «кто → кому → сколько» в копейках.
- План гарантированно минимален при `m ≤ 14` участниках с ненулевым балансом; при `m > 14` используется жадный алгоритм с честным указанием, что минимум не обещан.
- Результат детерминирован: переводы отсортированы по `(debtor, creditor, amount)`; нулевые балансы и пустая группа не дают переводов.
- Разбалансированные входные данные отвергаются с понятной ошибкой и кодом возврата CLI `2`.
- Добавляются примеры из спеки, property-тесты на маленьких суммах и оракул полного перебора для проверки оптимальности на `m ≤ 7`.
- Изменение создаётся ретроспективно: реализация уже зафиксирована коммитом `6219392`; OpenSpec-артефакты фиксируют принятое поведение и границы обещания.

## Capabilities

### New Capabilities

- `expense-settlement`: построение плана денежных переводов по балансам группы, включая гарантию минимального числа переводов на малых группах, правила вывода и обработку некорректных входных данных.

### Modified Capabilities

- Нет.

## Impact

- Код: `src/skinemsya/settle.py` (новый), `src/skinemsya/cli.py` (новая подкоманда `settle`).
- Тесты: `tests/test_settle.py` (примеры, инварианты, оракул, property-тесты).
- Документация: `docs/specs/settle-up.md`, `docs/adr/0002-settle-algorithm.md`, `docs/JOURNAL.md`.
- Зависимости и внешние сервисы не добавляются; реальные платежи не инициируются.
