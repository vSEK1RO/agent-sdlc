### 2 красный/зелёный `settle`: два фейла и ADR

**Фейл с разграничением прав доступа.** В `opencode.json` я запретил `read`/`edit` на `ASSIGNMENT.md` и `shell` по `*ASSIGNMENT*`, но забыл про `grep`. Агент честно сообщил, что `read` и `cat` падают с `Permission denied`, а затем спокойно вытащил весь файл построчно через `grep . ASSIGNMENT.md`. То есть «запрет читать задание» сработал только для двух инструментов, а не для всех способов чтения. Вывод: правила надо проверять прогоном по каждому инструменту, который умеет читать файлы (`read`, `shell`, `grep`, MCP-ресурсы), либо закрывать файл на уровне файловой системы. Если агент говорит «прочитал через grep» — это провал ограничения, а не его находчивость.

**Почему первый фикс не добился минимального числа переводов.** Фикс issue #1 (остаток копейки плательщику) восстановил инвариант `sum(balances) == 0`, но «балансы сходятся» — это ещё не план расчёта. Минимизация переводов — отдельная NP-трудная задача, и жадный вариант её не решает: на балансах Аня +600 ₽, Боря +400 ₽, Вика −400 ₽, Гоша −400 ₽, Дима −200 ₽ жадное слияние самого крупного должника с самым крупным кредитором даёт 4 перевода, а минимум — 3. Второй провал уже у агента: в первом прототипе DP он сравнивал число подгрупп с нулевой суммой не в ту сторону (`<` вместо `>`), то есть минимизировал количество групп вместо максимизации; Карелия получала 5 переводов вместо 4. Без property-теста с оракулом полного перебора мы бы назвали неоптимальный план «оптимальным».

**Как помог ADR-0002.** Он заставил зафиксировать критерий: число переводов равно `m − k`, где `k` — максимум непересекающихся подгрупп с нулевой суммой. Это сразу исправило знак сравнения и дало проверяемую формулировку для тестов. Замеры на `n = 10..17` показали экспоненциальный рост (≈0.3 с на 14 участников, ≈10 с на 17), поэтому решение стало гибридным: точный DP при `m ≤ 14`, жадный выше. В спеке честно написано «минимум только при `m ≤ 14`», так что агент больше не может сказать «оптимально» без оговорки. Итог: `examples/karelia.json` → 4 перевода, красный коммит (`cf91208`) перед зелёным (`6219392`), тесты после red менялись только стилистически ради `ruff`. Отдельно: коммиты сделаны прямо в `main`, ветку `feature/settle` не создавал — поправить до PR.
